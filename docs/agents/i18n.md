# i18n (Internationalization) — apps/web

The web app (`apps/web`) is internationalized with [`react-i18next`](https://react.i18next.com/).
Ukrainian (`uk`) is the **default and fallback** language; English (`en`) is also available.
This document is the source of truth for conventions so feature work can add translations
in parallel without merge conflicts.

## TL;DR for adding translations

1. Pick the right namespace file (or add a new one — see below).
2. Add the same key to **both** `src/locales/uk/<ns>.json` and `src/locales/en/<ns>.json`.
3. In a component: `const { t } = useTranslation('<ns>')` then `t('key')`.
4. Never hardcode user-facing strings — only brand tokens (e.g. `GYMTRACKER`) and runtime
   values (e.g. `__APP_VERSION__`) stay as literals.

## Directory layout — namespace per feature

```
apps/web/src/locales/
  uk/
    common.json     # shared atoms: days, language names, generic words
    nav.json        # bottom navigation labels
    settings.json   # Settings page
    <feature>.json  # NEW per-feature namespaces (dashboard, exercises, workout, ...)
  en/
    common.json
    nav.json
    settings.json
    <feature>.json
```

Each JSON file is **one namespace**. The `uk` and `en` files for a namespace **must have
identical key sets**. Keys are nested objects, e.g. `common.json` → `{ "days": { "mon": "Пн" } }`.

## Referencing keys

- Scoped (preferred): `useTranslation('settings')` → `t('title')`, `t('weightUnits')`.
- Cross-namespace from one hook: `useTranslation(['settings', 'common'])` → `t('title')`,
  `t('common:days.mon')`. The `<ns>:` prefix selects the namespace; the `.` is the key path.
- Default namespace is `common`, so `t('days.mon')` works when `common` is loaded.

Labels must be derived **at render** (inside the component, via `t(...)`), never frozen into a
module-level constant — otherwise they won't react to a language switch. See `AppLayout.tsx`
(`NAV` stores a `labelKey`, and `t(labelKey)` is called in the map body).

## Persistence approach (single mechanism)

Language is stored in the existing zustand **preferences store**
(`src/stores/preferences.store.ts`, localStorage key `gymtracker-preferences`) as
`language: 'uk' | 'en'` (default `'uk'`). There is intentionally **no** separate
`i18next-browser-languagedetector` cache — the store is the only source of truth, which
guarantees first load with no stored value resolves to `uk` (never the browser language).

Wiring (`src/lib/i18n.ts`):

- On init, `lng` is read from `usePreferencesStore.getState().language`.
- A `languageChanged` listener mirrors every change back into the store.
- The Settings Language card calls `i18n.changeLanguage(lang)` (and `setLanguage` for an
  immediate, explicit persist).

> `i18next-browser-languagedetector` is installed as a dependency but deliberately **not**
> wired into the init order, to keep the store as the single persistence mechanism. Do not
> introduce a second persistence path.

## Adding a NEW namespace (conflict-free for parallel work)

To add a feature namespace (e.g. `dashboard`):

1. Create `src/locales/uk/dashboard.json` and `src/locales/en/dashboard.json` (new files —
   no conflict with other features).
2. Register it in `src/lib/i18n.ts`:
   - import the two JSON files,
   - add `dashboard: <json>` under both `uk` and `en` in `resources`,
   - add `'dashboard'` to `I18N_NAMESPACES`.

`src/lib/i18n.ts` is the only shared file touched. Coordinate edits there to a single line
per namespace to minimize conflicts. Everything else is isolated new files.

> **FN-009b / FN-009c note:** Route-page translation (FN-009b) and component translation
> (FN-009c) must add their strings as **per-feature namespace JSON files** under
> `src/locales/{uk,en}/`. They should only append namespace entries to `i18n.ts`'s
> `resources`/`I18N_NAMESPACES` and must not otherwise edit shared config, to avoid conflicts.

## Running tests

```
npm run test --workspace=apps/web        # vitest run (jsdom)
```

Smoke coverage lives in `src/lib/i18n.test.ts`: default → `uk`, `changeLanguage('en')`
resolution, and persisted-choice restore on fresh init.
